## PART A — On Computer A: Build & Package a Release

### A.1 Build the JAR

Open PowerShell inside the project folder (Shift + right-click in the folder → "Open PowerShell window here"), then run:

```powershell

The exact location
C:\PROJECT TO BE DEVELOPED\animal-production

.\mvnw.cmd clean package -DskipTests
```

Wait for:
```
BUILD SUCCESS
```

### A.2 Find the JAR

```
C:\PROJECT TO BE DEVELOPED\animal-production\target\animal-production-0.0.1-SNAPSHOT.jar
```

(Ignore the `.jar.original` file next to it — not needed.)

### A.3 Confirm `application.properties` is ready

This file sits **outside** the JAR, in the delivery folder, and tells the app how to connect to the database on whichever computer it runs on:

```properties
spring.datasource.url=jdbc:postgresql://localhost:5432/db_animalproduction
spring.datasource.username=postgres
spring.datasource.password=Kigali@10
spring.datasource.driver-class-name=org.postgresql.Driver
spring.jpa.hibernate.ddl-auto=none
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true
spring.jpa.properties.hibernate.dialect=org.hibernate.dialect.PostgreSQLDialect
spring.jpa.properties.hibernate.jdbc.lob.non_contextual_creation=true
server.port=8888
```

Saved as: `D:\Desktop\LivestockManagerPro-Delivery\application.properties`
(Saved via Notepad → Save As → "Save as type: All Files" → typed exactly `application.properties`)

> `ddl-auto=none` is intentional and important — it means the app will **never** automatically change the database structure. This protects the tester's data. See Part D for how to handle real schema changes safely.

### A.4 Back up the database

```powershell
cd "D:\Desktop\LivestockManagerPro-Delivery"
& "C:\Program Files\PostgreSQL\15\bin\pg_dump.exe" -U postgres -d db_animalproduction -p 5432 -F c -f db_animalproduction_backup.dump
```

Enter password `Kigali@10` when prompted (nothing shows on screen while typing — that's normal).

### A.5 Confirm the delivery folder is complete

```powershell
dir
```

Should show:
```
D:\Desktop\LivestockManagerPro-Delivery\
├── animal-production-0.0.1-SNAPSHOT.jar
├── application.properties
└── db_animalproduction_backup.dump
```

### A.6 Zip it and send it

Right-click the `LivestockManagerPro-Delivery` folder → **Send to** → **Compressed (zipped) folder**. Transfer the `.zip` to Computer B (USB drive, cloud link, etc.).

## PART B — On Computer B: One-Time Setup (only needed the very first time)

### B.1 Install Java 21

1. Download from https://adoptium.net/ (Temurin JDK 21)
2. Install, checking "Set JAVA_HOME" and "Add to PATH" if offered

If not set automatically, do it manually:
1. Windows key → type `environment` → **"Edit the system environment variables"** → **Environment Variables...**
2. Under **System variables**, click **New...**
   - Name: `JAVA_HOME`
   - Value: `C:\Program Files\Java\jdk-21` (match your actual folder name exactly)
3. Select the **Path** variable → **Edit...** → **New** → add: `%JAVA_HOME%\bin`
4. OK everything, close all PowerShell windows, open a fresh one, verify:
```powershell
java -version
```

### B.2 Install PostgreSQL 18

1. Download from https://www.postgresql.org/download/windows/
2. During install, set the `postgres` superuser password to match your `application.properties` → `Kigali@10`
3. Keep port `5432`

### B.3 Create the database

```powershell
& "C:\Program Files\PostgreSQL\18\bin\psql.exe" -U postgres -p 5432
```
Then at the `postgres=#` prompt:
```sql
CREATE DATABASE db_animalproduction;
```
```
\q
```

## PART C — On Computer B: Install / Refresh the App

### C.1 Unzip

Extract the `.zip` into: `C:\LivestockManagerPro\`

### C.2 Restore the database backup

```powershell
cd "C:\LivestockManagerPro"
& "C:\Program Files\PostgreSQL\18\bin\pg_restore.exe" -U postgres -d db_animalproduction -p 5432 "db_animalproduction_backup.dump"
```
Enter password `Kigali@10` when prompted.

### C.3 Create the launcher (first time only)

New Text Document → paste:
```bat
@echo off
echo Starting Livestock Manager Pro...
echo Please wait, this can take up to a minute...
java -jar animal-production-0.0.1-SNAPSHOT.jar
pause
```
Rename to `run.bat` (make sure **View → Show → File name extensions** is turned on first, so the rename actually removes `.txt` and not just the visible label).

### C.4 Run it

Double-click `run.bat` → wait for:
```
Tomcat started on port(s): 8888
```
Open browser → `http://localhost:8888`

## PART D — Delivering Future Updates

### D.1 Code-only changes (no database structure changes)

**On Computer A:**
```powershell
.\mvnw.cmd clean package -DskipTests
```
Send **only** the new `animal-production-0.0.1-SNAPSHOT.jar` to Computer B.

**On Computer B:**
1. Close the app (`Ctrl+C` in the black window, or close it)
2. Replace the old `.jar` in `C:\LivestockManagerPro\` with the new one (same file name)
3. Double-click `run.bat` again

Data is untouched — it lives in PostgreSQL, separate from the JAR.

### D.2 Database structure changes (new column, new table, etc.)

Because `ddl-auto=none` protects existing data, structure changes need to be applied manually. Two options:

**Option A — Send a small SQL migration file (recommended, keeps tester's data)**

1. On Computer A, write down exactly what changed, e.g.:
   ```sql
   ALTER TABLE livestock ADD COLUMN breed_certification VARCHAR(100);
   ```
   Save as e.g. `update_2026-08-01.sql`
2. Send this file **along with** the new JAR to Computer B
3. On Computer B, before running the new JAR:
   ```powershell
   & "C:\Program Files\PostgreSQL\18\bin\psql.exe" -U postgres -d db_animalproduction -p 5432 -f update_2026-08-01.sql
   ```
4. Then run `run.bat` as normal

**Option B — Full refresh (only if it's OK to erase the tester's current data)**

1. On Computer A, after your DB changes: take a fresh `pg_dump` (see A.4)
2. Send new JAR + new `.dump` to Computer B
3. On Computer B:
   ```powershell
   & "C:\Program Files\PostgreSQL\18\bin\psql.exe" -U postgres -p 5432 -c "DROP DATABASE db_animalproduction;"
   & "C:\Program Files\PostgreSQL\18\bin\psql.exe" -U postgres -p 5432 -c "CREATE DATABASE db_animalproduction;"
   & "C:\Program Files\PostgreSQL\18\bin\pg_restore.exe" -U postgres -d db_animalproduction -p 5432 "new_backup.dump"
   ```
   ⚠️ This erases everything the tester entered since the last backup.

> **Long-term option:** a tool called **Flyway** can be added to the Spring Boot project to auto-apply only new SQL changes on startup, removing the need to manually run migration files each time. Worth considering if updates become frequent.


## Cheat Sheet

| Task | Command |
|---|---|
| Build JAR (Computer A) | `.\mvnw.cmd clean package -DskipTests` |
| Backup DB | `pg_dump.exe -U postgres -d db_animalproduction -p 5432 -F c -f backup.dump` |
| Restore DB | `pg_restore.exe -U postgres -d db_animalproduction -p 5432 "backup.dump"` |
| Apply SQL migration | `psql.exe -U postgres -d db_animalproduction -p 5432 -f update.sql` |
| Run the app | double-click `run.bat`, or `java -jar animal-production-0.0.1-SNAPSHOT.jar` |
| Check Java | `java -version` |
| App URL | `http://localhost:8888` |

## Troubleshooting

| Problem | Fix |
|---|---|
| `mvnw.cmd not recognized` | Make sure PowerShell is inside the project folder (`dir` to check) |
| `java not recognized` | Recheck JAVA_HOME + PATH, open a **new** PowerShell window after changes |
| Can't connect to DB | Check PostgreSQL service is Running (Services app), check port/password match `application.properties` |
| `Port already in use` | Something else is using 8888 — change `server.port` in `application.properties` |
| File renamed but still won't run as `.bat` | Turn on View → Show → File name extensions, then rename again removing `.txt` |
| `pg_restore` role/permission errors | Restore using `-U postgres` (superuser) |
